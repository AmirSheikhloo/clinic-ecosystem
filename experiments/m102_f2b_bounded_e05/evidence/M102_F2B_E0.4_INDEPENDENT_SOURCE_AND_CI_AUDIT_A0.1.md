## 3. Confirmed defects affecting contractual proof

### A0.1-01 — Final validator does not fail closed on a case marked FAIL/BLOCKED/UNVERIFIED

**Severity:** HIGH. **Classification:** `CONFIRMED_SOURCE_DEFECT / ACCEPTANCE_BLOCKER`.

At tested SHA, `harness/evidence.py`, lines **48–58**, admits `OBSERVED_FAIL`, `BLOCKED`, `NOT_RUN`, `UNVERIFIED` and `REVIEW_ONLY` into `ALLOWED_CLASSIFICATIONS`. In `validate_evidence_record()` lines **153–164**, it checks membership and checks exit-code coherence **only when** `classification == "OBSERVED_PASS"`; it does **not** require each of the 19 case records to be `OBSERVED_PASS`. In `verify_case_manifest()` lines **264–313**, the verifier verifies manifest paths, hashes and calls the same per-record checker, then returns accumulated errors **without requiring all 19 expected acceptance statuses to be PASS**. The concluding source comment at line **312** expressly acknowledges the missing overall rejection: “also reject any FAIL as overall if desired by caller”. The post-pytest gate in `scripts/post_pytest_forensic_verify.py` uses `ok = not errors` and exits successfully if no errors are returned.

**Counterfactual (static code-path proof; not an executed tamper test):** a properly formed case file classified `OBSERVED_FAIL` with its digest freshly reflected in an otherwise valid manifest is **not automatically denied** by this verifier. Hence a green forensic gate does not prove all 19 contractual cases passed—even though the **actual artifact inspected here really has 19/19 `OBSERVED_PASS` records**. The distinction is a control defect, not an allegation that this actual ZIP contains failed records.

**Required proof to close:** enforce exact expected per-ID `OBSERVED_PASS` with coherent exit/expected/observed state, require a complete 19/19 acceptance map, and execute a negative fixture that injects `OBSERVED_FAIL` (and `BLOCKED`/`UNVERIFIED`) with a **recomputed, internally valid digest manifest** and demonstrates the real final gate refuses it.

Source: <https://github.com/AmirSheikhloo/clinic-ecosystem/blob/8d015959ec6b2570da74d63d8f7ee0e88d1cff64/experiments/m102_f2b_bounded_e04/harness/evidence.py#L136-L235> and <https://github.com/AmirSheikhloo/clinic-ecosystem/blob/8d015959ec6b2570da74d63d8f7ee0e88d1cff64/experiments/m102_f2b_bounded_e04/harness/evidence.py#L264-L313>.

### A0.1-02 — Cross-record semantics, provenance fields and field types remain under-validated

**Severity:** HIGH/MEDIUM. **Classification:** `CONFIRMED_SOURCE_DEFECT / ACCEPTANCE_BLOCKER`.

`validate_evidence_record()` checks several important invariants (CI `GITHUB_SHA`, `GITHUB_RUN_ID` when present, contract SHA, historical E0.2 parent, timestamp parseability, basic path prefix, PG15 range and selected secret patterns). However it does **not** verify `case_id` against the file's basename/expected ID, expected `finding_id` or execution kind per case, `parent_e03_final_commit_sha` against the pinned E0.3 final parent, `run_attempt` against the runner, the actual existence or link integrity of every declared `evidence_files` reference, mandatory source/test linkage, or the exact type/semantic adequacy of required expected/observed/before/after fields. The implementation's per-field check is limited mainly to presence/nonempty values. A string with a nonempty but meaningless value can satisfy a field that requires structured proof. Its CI identity enforcement also becomes weaker if runner variables are absent, though the actual verified CI run did provide correct values.

The contract explicitly demands these binding/semantic checks in E0.4 §§5.2–5.4. The original artifact's case IDs, SHA and run IDs **do** match on independent read-only inspection; that does not retroactively establish that the automated validator enforces all negative cases.

**Required proof to close:** case-ID-to-filename and finding/kind matrix, pinned E0.3 parent, strict typed schema and provenance verification, source linkage and evidence-file path existence, and independent mutation tests that isolate each violated invariant. Allow `NOT_APPLICABLE` only for genuinely nonphysical fields with a recorded reason. Validate actual values and relationships, not just regex presence.

Source: `harness/evidence.py` lines **136–235**, and E0.4 contract §§**5.2–5.4**.

### A0.1-03 — Some E0.4 falsifiability fixtures test a surrogate, not the real required denial path

**Severity:** HIGH/MEDIUM. **Classification:** `CONFIRMED_TEST_COVERAGE_GAPS / ACCEPTANCE_BLOCKER`.

The CI executed all 14 fixture functions, but source inspection shows material gaps:

- **`E04-V03`** (`tests/test_z_e04_validator_fixtures.py` lines **131–~155**) deletes and corrupts IDs in a disposable copy, then calculates local set/duplicate conditions; it does **not call** `verify_case_manifest()` or the actual final verifier on that corrupted evidence tree. It therefore does not prove the production experiment validator rejects a wrong/duplicate embedded `case_id` after valid rehashing.
- **`E04-V04`** (same file, approximately lines **156–~195**) recomputes a **separate handwritten comparison** of one tampered file against the manifest; it does not exercise the actual manifest verifier on that altered tree. This establishes SHA-256 behavior, but not the stated end-to-end negative gate.
- **`E04-V13`** (lines **411–422**) passes when a nonexistent manifest generates an error; it does not inject a verifier failure into the workflow with a green pytest run and **observe** a red job. The workflow structurally uses `set -euo pipefail`, which is encouraging, but is not a substituted execution trace.
- **`E04-V14`** (lines **425–440**) contains `assert manifest.exists() or True`, which is unconditionally true, and permits a `MANIFEST_NOT_YET_WRITTEN_AT_FIXTURE_TIME` outcome while marking the fixture `OBSERVED_PASS`. The actual observed V14 record states `VALIDATOR_OK_PENDING_INDEPENDENT_AUDIT`, so this branch was not triggered in the successful CI run; nevertheless the test's acceptance condition is logically insufficient.
- **`E04-V07`** provides multiple simultaneously invalid attributes and asserts an error on *either* timestamp or missing preconditions; it does not independently test rejection of each bad type. **`E04-V11`** similarly combines malformed digest and self-hash into one fixture with a generic `assert errors`. These cannot by themselves prove each enumerated negative requirement independently.

**Required proof to close:** update fixtures to invoke the exact real final validator or an equivalently injected real CLI gate with controlled disposable manifests, observe and assert the specific rejection reason, and remove every unconditional/pass-on-missing success path. Do not alter original physical PG15 test semantics or reinterpret old runs.

Sources: <https://github.com/AmirSheikhloo/clinic-ecosystem/blob/8d015959ec6b2570da74d63d8f7ee0e88d1cff64/experiments/m102_f2b_bounded_e04/tests/test_z_e04_validator_fixtures.py#L131-L195> and <https://github.com/AmirSheikhloo/clinic-ecosystem/blob/8d015959ec6b2570da74d63d8f7ee0e88d1cff64/experiments/m102_f2b_bounded_e04/tests/test_z_e04_validator_fixtures.py#L411-L440>.

### A0.1-04 — Final artifact digest inventory does not independently bind all auxiliary evidence

**Severity:** MEDIUM. **Classification:** `CONFIRMED_LIMITATION / CONTRACT_INTERPRETATION_REVIEW_REQUIRED`.

The independently verified manifest hashes **19 case JSONs**. JUnit, pytest output, 14 `E04-V*.json` records, `POST_PYTEST_FORENSIC_VERIFIER.json`, raw CI log, source ledger and final report are **not** listed in a second cryptographically bound layer in the downloaded artifact. E0.4 §5.1(6) calls for either inclusion of *mandatory* additional stable raw evidence or an explicit second digest inventory; §5.4 allows optional logs/JUnit only when stable, otherwise by a later layer. It is therefore **not justified to assert every auxiliary file was contractually required to be hashed** without further interpretation. Nevertheless a claim of *full package-level forensic integrity* is not supported merely by the verified 19-case manifest. The actual immutable Actions artifact and commit associations materially improve traceability. The final report correctly restricts its digest claim to the case manifest.

**Resolution:** independent reviewer should explicitly determine which auxiliary pieces are mandatory for E4-E and whether digest coverage should be extended under a new grant. Do not convert this interpretive item into an allegation of changed or falsified artifacts.
