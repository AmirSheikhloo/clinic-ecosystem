## Purpose

Populate the receptionist / operations preview with a realistic, version-controlled synthetic dataset so dashboards, lists, waiting queues, overlaps, and multi-service groups are never empty.

## Profiles

| Profile | Use | Notes |
|---------|-----|-------|
| `minimal` | Fast local/unit structure checks | Small counts |
| `demo` (default) | Preview stack | Meets D0.5 minimums |
| `performance` | Stress stub | Larger targets; same generator |

Targets are declared in `profiles.py` and mirrored in `scripts/demo_dataset/manifest.json`.

## Preview invocation

`scripts/start_preview_stack.py` → `tests.e2e.beta01b.stack.start_browser_stack`:

1. Migrate tenant plane (tp0001–tp0007)
2. `seed_beta02_operations` (roles + baseline receptionist)
3. Set deterministic `CLINIC_ENV=preview` + `CLINIC_PII_*_HEX` keys
4. `load_demo_dataset(..., profile=CLINIC_DEMO_PROFILE or "demo")`
5. Write `demo_dataset_manifest.json` under the artifact directory

Override profile with `CLINIC_DEMO_PROFILE=minimal|demo|performance`.

## CLI

```bash
# Load (migrator DSN; tenant + receptionist person from prior seed)
python scripts/demo_dataset/generate_demo.py \
  --dsn "$MIGRATOR_DSN" \
  --tenant-id "$TENANT_ID" \
  --receptionist-person-id "$PERSON_ID" \
  --receptionist-account-id "$ACCOUNT_ID" \
  --profile demo \
  --ensure-preview-keys \

  --dsn "$MIGRATOR_DSN" \
  --tenant-id "$TENANT_ID" \
  --profile demo \
  --require-crypto
```

## Integrity notes

- Synthetic data only — National IDs and phones are generated, never real PII.
- Inserts run as `db_migrator` with `app.current_tenant_id` GUC; RLS is not disabled.
- Appointment statuses are only values already used by the product (`CONFIRMED`, `CHECKED_IN`, `COMPLETED`, `CANCELLED`, `NO_SHOW`).
- Intentional overlaps use `capacity_pool=MANUAL` / `booking_channel=MANUAL_STAFF` (ONLINE GiST EXCLUDE does not apply).
- A small ONLINE sample uses non-overlapping slots so GiST EXCLUDE is respected.
- Multi-service groups share `patient_booking_note` prefix `GROUP:…` on the same patient/day.
- Exceptional identity patients use dossier `EXC-…` and audit `identity_exception_reason`.
- Encrypted `person_identifiers` / `person_phones` are seeded only when non-prod `CLINIC_ENV` and `CLINIC_PII_*` keys are present; otherwise hooks skip crypto rows and validation notes the skip.
- No finance/inventory tables exist under tp0001–tp0007 — none are invented.
- Dates are anchored to **Asia/Tehran** “today” at generation time so the dashboard stays populated across calendar days.
